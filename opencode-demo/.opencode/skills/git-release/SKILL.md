# Git 版本发布准备流程

当维护者需要准备版本或评估是否可以发布时，使用本 Skill。

## 安全约束

除非用户明确要求更新本地变更日志或版本文件，否则本流程必须保持只读。不得执行 `git push`、创建 Tag、执行 `mvn deploy`、创建远程 Release 或部署服务。

## 执行步骤

1. 阅读 `AGENTS.md` 和 `pom.xml`。
2. 检查 `git status --short`，说明工作区是否干净。
3. 如果存在版本 Tag，找出当前可达的最新版本。
4. 根据最新版本之后的提交和当前差异，总结用户可感知的变更。
5. 将变更分为破坏性变更、功能、修复、文档或内部调整。
6. 建议语义化版本升级，并用一句话解释原因。
7. 在权限允许时运行 `AGENTS.md` 中规定的验证命令。
8. 起草简洁的中文发布说明。
9. 输出发布检查表，每项明确标记为通过、失败或未知。

## 必须输出

- 当前版本和建议版本。
- 工作区状态。
- 实际执行的验证命令及结果。
- 用户可感知的变更摘要。
- 兼容性或迁移说明。
- 中文发布说明草稿。
- 剩余阻塞项。

如果版本约定不明确，必须先询问，不能自行假设。
